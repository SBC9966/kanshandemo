# 看山不是山 · 产品说明与提交计划书

> 参赛活动：知乎黑客松 2026 校园新锐季（`zhihu_hackathon_2026_p2`）
> 本文用途：提交材料之二「产品说明或计划书」；同时作为提交前自查清单。
> 资料核对说明：赛程与提交要求来自本地 `zhihu` skill 内抄录的官方文档（核对日期 2026-09-03）与活动群通知；**活动页面最终展示为准**，飞书两篇原始文档需登录，本项目侧未直接读取。

## 一、一句话定位

**把「刷到一条讨论」变成「走完一条知识路径」**：六座知识山，每座五层营地，每层先摆真实材料与出处，再让你亲手做一个互动实验，最后用一次理解确认把话说清楚；走完五层，山顶会把你这一路的判断连成一张脉络图。

面向的是这样的人：对某个话题有兴趣，但受够了"三分钟看完""十条金句"——想要一条**有出处、可追问、能检验**的路径。

## 二、目标用户与场景

| 场景 | 今天的替代方案 | 我们给出的东西 |
|---|---|---|
| 想入门一个概念（如"存在主义"） | 搜索引擎 + 短视频，信息零散 | 五层营地：认识 → 背景 → 核心 → 分歧 → 延伸 |
| 想知道"大家到底在争什么" | 直接翻评论区，容易被情绪带走 | 明确区分「知乎讨论入口」与「公开参考页」，并标出本次实际读取范围 |
| 想检验自己是不是真懂了 | 缺少反馈 | 每层一个互动实验 + 一次理解确认，答错有解释、答对才解锁下一站 |
| 想留下点什么 | 收藏夹吃灰 | 山顶生成脉络图与考察手记，可导出 Markdown |

## 三、核心体验（评委可实际操作的流程）

1. **选一座山**（首页六张卡，或一句话开一条自定主题的路）。
2. **进一层营地**：第一屏是「先看材料」——本地策展出处 + 知乎真实回答摘要（带原文链接）；往下才是互动实验与理解确认。
3. **亲手探索**：分类、排序、配对、视角选择、反思五类实验，操作会真实改变实验状态（不是点一下播动画）。
4. **理解确认**：三选一的判断题，答完给出解释；实验 + 确认都完成，这一站才算走过。
5. **下一站引导**：每站完成即在原地弹出「进入下一站」，完成后直接落到下一站，不用自己回地图找。
6. **山顶一览**：五层走完进入山顶页——一条脊线串起五站的脉络图（含概念标签与带走的判断）、六座山的进度一览、跨山路径。
7. **随身向导「阿山」**：侧边小狗向导，按当前位置给解释与材料，答案全部来自本地检索并带出处；命中不足会直说"没有足够匹配"，不编答案。

**路演模式**：前三层营地默认开放（便于评委直接看内容），后面的营地按真实完成度依次解锁。

## 四、技术方案

- **前端**：零依赖原生 ES Module + 单文件打包产物（`dist/index.html`，插画/脚本/样式全部内嵌），可离线打开；无框架、无 CDN、无外链字体。
- **3D 山体**：内置 three.js（vendored）微缩沙盘，程序化山体 + 盘山小径 + 五站装置，60fps 自动运镜与自由观察，随用户行为切换。
- **本地知识层**：49 条策展来源（其中 33 条知乎问题/专栏入口、16 份公开参考），带读取范围（`page-read` / `index-only`）、用途与出处；本地检索引擎（分词 + 打分）驱动向导与资料馆检索。
- **服务端**：一个 Node 静态/代理服务（无第三方依赖），负责静态托管与知乎开放平台代理；**Access Secret 只留在服务端**。
- **开放平台接入的工程化**：所有知乎调用经服务端代理 + **磁盘缓存**（`.zhihu-cache.json`，按接口分档 TTL），页面刷新不重复消耗额度；额度耗尽时降级为「最近一次快照 + 明确标注快照时间」，不伪造成功。
- **纯函数时间轴**：3D 沙盘与所有动画都是 `day` 的纯函数（无 `Math.random`/`Date.now`），可重放、可截图、可录屏。

## 五、使用了哪些知乎开放能力

| 能力 | 接口 | 项目里的用法 |
|---|---|---|
| 站内检索 | `/api/v1/content/zhihu_search` | 资料馆「实时搜知乎」 |
| 全网检索 | `/api/v1/content/global_search` | 资料馆的全网来源补充 |
| 热榜 | `/api/v1/content/hot_list` | 「此刻知乎热榜」；并按主题关键词匹配到各座山（命中词如实回显） |
| 问题回答摘要 | `/api/v1/content/question_answers` | 节点页与来源详情的「真实回答片段」（服务端摘要 + 看原回答） |
| 问题推荐 | `/api/v1/user/question_recommendations` | 每座山的「此刻大家在讨论什么」 |
| 黑客松内容接口 | `api.zhihu.com/km-indep-home/hackathon/v2/{knowledge,story}/list` | 资料馆「知乎知识作品」货架（免鉴权、不占额度） |
| 额度查询 | `/api/v1/quota` | 预热脚本与降级判断 |
| OAuth（未接入） | — | 本作品不需要读取用户创作/关注/收藏，因此**不申请 OAuth**，也不索取任何用户授权 |

**工程约定**：回答只展示服务端返回的摘要片段并给原文链接，不复制全文；不展示/不推测赞同数与浏览数；不把知乎内容改写成本项目创作。

## 六、与知乎生态的契合点

1. **把社区讨论当作一等材料**，而不是附在结尾的"相关链接"：每一层营地的第一屏就是材料与出处，知乎真实回答片段直接贴在页面里并可点进原文。
2. **诚实优先**：能读到什么就说读到什么（`已读相关段落` / `仅检索摘要`），取不到就说取不到（离线、额度耗尽、空数据都有独立文案）。
3. **不滥用额度**：代理层做了磁盘缓存、请求去重与限流，一次预热把当日额度摊薄成一次调用；热榜改成"取一次全量、按需切片"。
4. **回馈社区**：用户走完一站留下的判断可导出为考察手记（含出处与检索记录），鼓励把"我读到了什么"带回讨论，而不是复制粘贴结论。

## 七、社区价值

- 给"想认真了解一个话题"的普通用户一条**可核查的路径**，而不是又一份答案清单。
- 给优质知乎讨论**新的入口**：从"话题旁边"变成"学习路径上的必经一站"。
- 给内容消费一个**可停止的终点**：山顶的脉络图与手记，是"我已经走完了"的明确信号。

## 九、部署建议（把 Demo 变成公开可访问）

产物有两种形态，按时间预算选择：

**A. 最低成本（5 分钟，静态托管）**
把构建产物 `index.html` 直接上传到任意静态托管（知乎内可用的对象存储、GitHub Pages、Netlify Drop、Vercel 静态站点等）。
- 优点：单文件、离线可用、零配置。
- 代价：知乎实时能力不可用（页面会如实显示"暂时取不到"），资料馆仍可用本地 49 条策展资料。

**B. 完整体验（推荐，需要 Node 运行环境）**
部署整个工程（`server/index.mjs` + `dist/index.html`），设置环境变量：
```
ZHIHU_API_KEY=<Access Secret>        # 仅服务端，勿进仓库
PORT=8787
```
启动：`node server/index.mjs`。首次部署后运行 `node scripts/zhihu-warm.mjs` 预热缓存（当日额度内取回回答、推荐问题、知识作品与热榜快照）。
- 可选平台：Render / Railway / Fly.io / 自建 VPS；任何能跑 Node 20+ 的环境都可以。
- 若后续接入 OAuth：回调地址必须与赛事页面登记值完全一致。

## 十、已知边界（不写成"已实现"的部分）

- 知乎内容的"赞同数/浏览数"一律不展示（接口也不返回），不做热度排序。
- 五层内容的"分歧层"是编辑归纳的视角，不是对知乎回答的统计结论；页面上有明确标注。
- 3D 沙盘是示意性微缩舞台，不是测绘地形；六座山共用同一套山形骨架，差异在配色、天气、植被与文案。
- 本地检索是关键词打分，不是语义模型：命中不足时会直接说"没有足够匹配"，并给出去资料馆检索的出口。
- 额度：`question_answers` 与热榜额度较紧（10/日、2/日），因此缓存与降级是产品的一部分，而不是临时补丁。
